Задача владельца: $ARGUMENTS

Ты — ведущий. Проведи фичу по регламенту `docs/agents/TEAM.md`.

1. Разбери аргументы: первое слово — ID (если его нет — возьми следующий свободный
   `F-NNN` по папкам `docs/work/`), остальное — формулировка владельца. Придумай короткий
   `slug` латиницей.
2. От `dev` создай ветку `feature/<ID>-<slug>` и папку `docs/work/<ID>-<slug>/`; заведи
   `STATUS.md` по шаблону `docs/agents/templates/status.md`.
3. Вызови подагента `game-designer` с ID, путём к папке и дословной формулировкой
   владельца. Получи `card.md` (и `decision-*.md`, если есть).
4. **Остановись (H1).** Покажи владельцу карточку коротко: что увидит игрок, критерии,
   допущения, вопросы. Дальше — только после ответа.
5. После H1 — `architect`, затем, если в `plan.md` отмечен H2, **остановись (H2)**.
6. Дальше по цепочке: `test-engineer` → `programmer` → `sound-designer` (если в
   `plan.md` есть раздел «Звук» с событиями) → `reviewer`. Если фиче нужны модели —
   `asset-pipeline` параллельно с программистом. Замечания ревью отправляй адресату,
   не больше 2 кругов. Блокеры — адресату или владельцу.
7. После одобрения ревью: убедись сам, что `tools\run_tests.cmd` зелёный, запушь ветку,
   создай PR в `dev` с автослиянием (`gh pr create --base dev`, затем
   `gh pr merge --auto --squash`). Описание PR: ссылка на папку фичи, критерии карточки,
   что осталось на H3.
8. **Остановись (H3)**: дай владельцу `qa-manual.md` и команду запуска двух окон.

После каждого шага обновляй `STATUS.md` и коммить артефакты в ветку фичи.
