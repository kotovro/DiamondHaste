### Сеть: что проверил (по заданию ведущего)

- **Кто судит касание.** Своё тело судит владелец: проверка
  `Obstacle.judges_here(PLAYER, body.is_multiplayer_authority(), …)`. Чужой персонаж
  игнорируется. Свободный алмаз судит только хост. Несомый алмаз на слое 0 и луч не
  задевает (T-06).
- **Проверка запроса хостом.** Слепо хост клиенту не верит. Он проверяет `is_server()`.
  Отправителя берёт из `get_remote_sender_id()`, а не из данных запроса, и требует, чтобы
  у отправителя был существующий персонаж (`_has_player`). Затем применяет правило логики
  `touch.counts(PLAYER)` (взведён, не сработал). Точку прижимает к отрезку луча.
  Расстояние до луча хост не проверяет. Так задумано в плане ради К14: игрок может
  сообщить только о себе, а ложный отчёт навредит только самой команде. Пожелание — в
  замечании 8.
- **Пути RPC.** `Section/Obstacles/LaserBeam` и `Section` лежат в `test_level.tscn` внутри
  `main.tscn`, поэтому пути совпадают у всех пиров с запуска (как у `Diamond`).
- **Один сброс на одно срабатывание.** Первая защита — `touch.trip()`: событие с
  `call_local` применяется синхронно на хосте. Дальше `report_caught` отбрасывает новые
  причины, пока идёт `rules.is_alarm()`, а на паузе все препятствия сняты с взвода. Таймер
  есть только на хосте, `_on_reset_timer_timeout` защищён `is_server()`. Препятствия
  взводятся снова только после `respawn` своих персонажей и `reset_to_start` алмаза, так
  что сразу после сброса луч сам не срабатывает.
- **Отключение партнёра на паузе.** Таймер и алмаз ведёт хост. Сброс трогает только
  персонажей этой машины (`_local_players`: `is_instance_valid`,
  `is_queued_for_deletion`). Алмаз из рук отключившегося кладёт
  `Diamond._on_peer_disconnected`.
- **`is_instance_valid` после await и таймеров.** В коде фичи `await` нет. После таймера
  проверяются `_diamond` и препятствия. Твины привязаны к своим узлам.
- **Опрос в `_process`.** Опроса нет. Мигание и затемнение сделаны твинами, пауза —
  `Timer`. В `_physics_process` персонажа добавлен только флаг блока для непрерывного
  движения.
- **Подключившийся во время паузы.** `_apply_full_state` переводит секцию в `ALARM` и
  снимает препятствия с взвода, последующий `_apply_section_reset` возвращает `ACTIVE`.
  Состояние «луч сработал» новичку не передаётся (замечание 4).
- **Звук.** RPC ради звука нет. `LaserAudio` и `SectionAudio` только подписаны на сигналы
  и состояние игры не меняют. Громкости вынесены в конфиги. Новая раскладка шин —
  T-21, принята на H2. Петли (`smpl`) проверены тестом.
- **Тексты.** Новых текстов для игрока нет, поэтому `tr()` не нужен. Старые строки без
  `tr()` уже записаны в журнале как расхождение.
- **Godot.** API из 4.5+ не используется. У каждого нового скрипта есть `.uid`. В сценах
  нет выдуманных `uid://`. `project.godot` не менялся. Существующие `data/*.tres` не
  тронуты. Тесты меняли только коммиты `tests:`, старые тесты лишь дополнены, ни один не
  ослаблен. 0 orphans.

## Что хорошо

- Все три причины сброса сходятся в один вход `SectionRoot.report_caught`. Логика
  `SectionReset` и `LaserTouch` вынесена в чистые классы с юнит-тестами. Так «одна
  тревога — один сброс» и «разрушение = поимка» держатся на одном пути, а не на
  совпадении кода.
- Правило «кто судит касание» стало функцией логики `Obstacle.judges_here`. Виновника хост
  берёт из `get_remote_sender_id()`, а не из данных запроса. Касание проверяется дважды:
  у судящего и на хосте.
- Тесты снимают состояние ровно в момент `section_reset` (`_snapshot`). Бросок сквозь луч
  считается по конфигу алмаза и проверяет, что алмаз действительно прошёл луч. В
  `qa-manual` есть отдельный пункт, где отключается сам задевший (№ 22).
