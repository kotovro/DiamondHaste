# Препятствия и сброс секции — техзадание

Статус: разделы 1–5 приняты (H2 2026-11-20, T-16…T-20); раздел 6 — предложено (DIA-5,
ждёт H2: T-23, T-25, T-34…T-36). Журнал — `00-index.md`.
Правила кода — `ARCHITECTURE.md` («Секции и препятствия», «Сеть»). Термины — `DESIGN.md`:
поимка, сброс секции, чекпоинт, носильщик.

## 1. Препятствие

**Состав.** Сцена в `scenes/props/<имя>.tscn` (работает без уровня) + `<Имя>Config` в
`scripts/obstacles/` с `.tres` в `data/` + класс логики `RefCounted`. Общий базовый класс
узлов не заводим (`ARCHITECTURE.md`, «Композиция»): общий набор — утиный контракт ниже,
его проверяет контрактный тест `tests/integration/test_obstacle_contract.gd`.

**Контракт узла препятствия** (корень сцены):

| Что | Сигнатура | Смысл |
|---|---|---|
| группа | `obstacles` | секция находит свои препятствия среди потомков |
| сигнал | `tripped(target: int, actor_id: int, point: Vector3)` | сработало; на всех пирах, от хоста |
| метод | `set_armed(armed: bool) -> void` | секция взводит и снимает препятствие на всех пирах |
| метод | `is_armed() -> bool` | |
| метод | `get_consequence() -> int` | `Obstacle.Consequence` из конфига |
| поле | `config` (свой `*Config`, не `null` после `_ready`) | |

`target` — `Obstacle.Target` (`PLAYER`, `DIAMOND`); `actor_id` — peer id задевшего игрока
или `0` для алмаза.

**Последствие** — поле конфига (`Obstacle.Consequence`): `NONE` (только тревога
препятствия: свет и звук, без сброса) или `SECTION_RESET` (поимка). Новые последствия
(урон алмазу и т.п.) — новым значением перечисления, код секции разбирает его в одном
месте.

## 2. Кто судит касание

Правило `ARCHITECTURE.md` («Сеть») в виде функции логики `Obstacle.judges_here()`:

| Что коснулось | Судит | Как сообщает |
|---|---|---|
| персонаж (с алмазом или без) | владелец этого персонажа | `request_report_player_touch(point)` хосту (`rpc_id(1)`; у хоста — `call_local`) |
| персонаж другого игрока | никто на этой машине | игнорируется |
| свободный алмаз (лежит, летит) | хост | вызывает правило сразу, без RPC |
| несомый алмаз | — | у него нет коллизий (T-06); его «касание» — касание тела носильщика |

Хост не проверяет расстояние до луча: игрок может сообщить только о себе и вредит этим
только себе, а проверка на хосте вернула бы спор под задержкой (К14 F-001). Хост
проверяет: отправитель — владелец существующего персонажа, препятствие взведено.

Последствие выбирает хост: препятствие рассылает событие `_apply_tripped`, а
`SectionRoot` на хосте по `get_consequence()` решает, что делать.

## 3. Лазер (`LaserBeam`)

- Луч — отрезок вдоль локальной оси X узла, длиной `length` (экспорт узла, ставит
  левел-дизайнер по ширине прохода), на высоте `config.beam_height` над началом узла
  (начало узла — на полу посередине прохода).
- Зона касания (`Area3D`, `collision_layer = 0`, `collision_mask = 6` — слои `players` и
  `diamond`, `monitorable = false`) — `BoxShape3D (length, thickness, thickness)`; видимый
  луч — `CylinderMesh` диаметром `thickness` той же длины. Оба строятся в `_ready` из одних
  и тех же чисел: зона касания совпадает с видимым лучом (Д9 F-001).
- Фильтр «реагирует ли на алмаз» — в логике (`LaserTouch.counts`), а не в маске: маска
  одна на оба значения настройки.
- Видимость в Compatibility: материал `UNSHADED` (светится сам, не зависит от освещения и
  от glow), излучатели — такие же меши; рядом `OmniLight3D` малой энергии, в тревоге —
  мигает. Мигание — `Tween` с циклами, не `_process`.

## 4. Сброс секции

**Узел `SectionRoot`** (группа `sections`, стабильный `section_id`) — единственная точка,
куда сходятся все причины сброса. Логика состояния — `SectionReset` (`ACTIVE` → `ALARM` →
`ACTIVE`).

```
причина (на хосте)                     все пиры
──────────────────                     ─────────────────────────────────────────
obstacle.tripped (SECTION_RESET) ┐
diamond.destroyed                ├─► report_caught(cause, actor)
                                 │     rules.begin() == false → ничего (одно срабатывание)
                                 │     _apply_alarm_started.rpc(cause, actor) ─► rules.begin, все
                                 │                                               препятствия set_armed(false),
                                 │                                               блок управления своего
                                 │                                               персонажа, alarm_started
                                 │     ResetTimer.start(reset_delay)
ResetTimer.timeout (хост) ───────┴─► diamond.reset_to_start()  (события алмаза RESTORED + прочность)
                                      _apply_section_reset.rpc() ──────────────► rules.finish, свой
                                                                                 персонаж respawn() и
                                                                                 разблокирован,
                                                                                 set_armed(true),
                                                                                 section_reset(section_id)
```

- **Одно срабатывание — один сброс:** повторные причины во время `ALARM` отбрасывает
  `SectionReset.begin`; препятствия к тому же сняты с взвода и не шлют отчёты.
- **Отключение второго игрока во время паузы** ничего не ломает: таймер — на хосте,
  сброс трогает только персонажей, которыми машина владеет; алмаз из рук отключившегося
  кладёт `Diamond._on_peer_disconnected`, сброс возвращает его на постамент.
- **Подключение во время паузы:** хост шлёт новому пиру `_apply_full_state(alarm, cause,
  actor)`.
- **Порядок событий** гарантирует один канал надёжных RPC: события алмаза
  (`RESTORED`, прочность) приходят раньше `section_reset`.
- **Нулевой чекпоинт (F-001, T-18):** точки появления — группа `spawn_points`, алмаз —
  `Diamond._start_transform` (постамент). Пересоздания `Content` пока нет: в тестовой
  сцене у препятствий нет состояния, кроме взвода. Когда появится препятствие с
  состоянием (движение, патруль), сброс переходит на пересоздание `Content` (T-14), а
  `set_armed(true)` при сбросе становится лишним.

## 5. Числа (конфиги)

- `LaserConfig` (`data/laser_config.tres`): высота и толщина луча, реакция на алмаз,
  последствие, цвета, мигание, свет.
- `SectionConfig` (`data/section_config.tres`): пауза до сброса, блок управления на время
  тревоги, длительность затемнения.
- Звук — `LaserAudioConfig`, `SectionAudioConfig` (звуковой дизайнер).

Поля с типами и заглушками — в `docs/work/F-001-first-obstacle/plan.md`.

## 6. Уточнения DIA-5 (предложено)

Закрывают замечания ревью F-001 № 4, 5, 8 и переводят сброс на уровень с чекпоинтами
(`game-flow.md`, раздел 3).

- **Вход сброса — `LevelRoot.report_caught`** (T-23). Правило T-17 то же: все причины в одну
  точку, одно срабатывание — один сброс, пауза `reset_delay` на хосте. Меняется место:
  `SectionRoot` подключает свои препятствия к `LevelRoot`, тревогу и RPC
  (`_apply_alarm_started`, `_apply_section_reset`, `_apply_full_state`) ведёт `LevelRoot`.
- **Сброс пересоздаёт `Content` текущей секции** (T-25, вместо временного T-18):
  препятствия с состоянием (подвижный луч, учебный ящик) возвращаются в исходное
  пересозданием. `set_armed(true)` при сбросе остаётся для секций, чей `Content` не
  пересоздаётся (пройденные и будущие), и для секций без `content_scene`.
- **Полное состояние препятствия** (№ 4, T-34): `LaserBeam._apply_full_state(tripped: bool,
  point: Vector3)` — `authority`, `call_remote`, `reliable`, хост шлёт по `peer_connected`;
  после применения — `full_state_applied()`. Сработавший луч у подключившегося мигает,
  искра на месте. Сирена, затемнение и поза виновника догоняют по
  `LevelRoot.full_state_applied` (`game-flow.md`, раздел 6). Известного ограничения больше
  нет; в `qa-manual` DIA-12 — проверка «подключиться во время паузы».
- **`Consequence.NONE` — полный контракт** (№ 5, T-35): препятствие с последствием, которое
  не сбрасывает секцию, **перевзводит себя само**: хост через `LaserConfig.rearm_delay:
  float` — с — `2.0` (`Timer`) рассылает `_apply_rearmed()` (`authority`, `call_local`,
  `reliable`) → `set_armed(true)` и `calmed` на всех пирах. Реализуется с первым
  препятствием, которому `NONE` нужен; до этого контент-тест запрещает `NONE` в
  `data/*.tres` и сценах секций (так не останется луча, который мигает до сброса).
- **Допуск правдоподобия отчёта** (№ 8, T-36): хост принимает
  `request_report_player_touch`, только если синхронизированная позиция персонажа
  отправителя не дальше `LaserConfig.report_tolerance: float` — м — `3.0` от отрезка луча
  (`Obstacle.report_plausible(position: Vector3, segment: PackedVector3Array, tolerance:
  float) -> bool`, логика, юнит-тест). Под 150 мс персонаж сдвигается меньше чем на 1 м,
  подвижный луч — на 0,15 м, поэтому К14 F-001 и К35 DIA-14 не страдают; явно ложные
  отчёты отсекаются. Тот же приём — для отчёта о чекпоинте (`CheckpointConfig.report_tolerance`).
